# 0039. Git stacks and saved Git credentials

- **Status:** Accepted
- **Date:** 2026-11-20

## Context

Users keep their compose files in Git and want a stack to follow a repository: clone it, deploy
it and update it by pulling (#37), with private repositories reachable through credentials saved
once and shared by several stacks (#93). Webhooks (#38) and polling (#39) build on this later.

## Options considered

- **Git implementation:** the host's `git` binary (another runtime dependency, credential
  helpers and `GIT_SSH_COMMAND` per call, option injection through refs and URLs) or go-git
  embedded in nerdui (pure Go, auth objects per call, no host dependency). go-git lacks some
  features (partial clone, some protocol v2 paths), which a shallow clone of one ref does not
  need.
- **Where the clone lives:** in the stacks directory next to managed stacks (a pull could
  overwrite user files, and adoption scans would see it) or in its own `<data-dir>/git/<name>`.
- **Editing the compose file:** editable with local changes (every pull needs a merge) or
  read-only, with Git as the only source.
- **Credentials:** per stack (repeated for every repository of an account) or a shared list
  referenced by stacks. Encryption at rest would need a key next to the database, so it protects
  nothing on a single host; secrets are stored like registry passwords (ADR-0019): readable only
  by the user running nerdui.
- **SSH host keys:** skip verification (open to interception), require a known_hosts file, or
  trust on first use and refuse changed keys.

## Decision

- go-git v5, embedded. A stack is cloned with depth 1, one branch or tag, no tags or submodules,
  into a temporary directory renamed to `<data-dir>/git/<name>` (mode 0700) when complete;
  failures leave nothing behind. URLs are `https://`, `http://`, `ssh://` or `git@host:path`;
  passwords in URLs are refused, refs are validated, and the compose path must stay inside the
  clone (no `..`, no `.git`).
- A new stack mode `git`, listed with managed and external stacks. Its directory is the
  directory of the compose file in the clone; the compose file is read-only in the editor and
  the API (409), while `.env` stays local, untracked and survives pulls.
- Pull fetches the ref, resets tracked files to its newest commit and keeps untracked ones. With
  `redeploy`, `compose up --remove-orphans` follows when the commit changed (or always with
  `force`). A failed pull keeps the previous commit and records its error in `git.lastError`.
  Clone and pull run as jobs (`stack.git-clone`, `stack.git-pull`).
- Removing a Git stack deletes its row and clone; it is refused while the project has
  containers, and needs the stack name as confirmation.
- Credentials (`/git/credentials`): kind `token` (HTTPS user name and token/password) or `ssh`
  (private key, optional passphrase, or an ed25519 key generated by nerdui whose public key is
  shown for a deploy key). Secrets are write-only: an empty secret on update keeps the stored
  one. A credential used by a stack cannot be deleted; changes apply on the next pull.
- SSH host keys are trusted on first use and stored in the database; a changed key fails the
  pull until an administrator forgets the host under Settings → Git credentials.
- Permissions: `stacks:write` to create and remove, `stacks:deploy` to pull and to deploy after
  cloning, `settings:read` / `settings:write` for credentials and host keys.

## Consequences

- No new host dependency; the binary grows by go-git.
- Database migration 12 adds `git_credentials`, `git_stacks` and `git_known_hosts`.
- Secrets in the database are as protected as the data directory; backups of it contain them.
- Changes to a Git stack's compose file go through the repository; local edits are only
  possible in `.env`.
- Large repositories cost disk and time once per stack; shallow clones keep that small.
